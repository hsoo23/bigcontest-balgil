# 협업 규칙

셋이 18일 안에 병렬로 일하면서 **서로 깨뜨리지 않기 위한 최소 규칙**입니다. 10/10 회의에서 확정합니다.

---

## 1. 브랜치

같은 `features.py`를 수경(카드 쪽)과 현수(상가 쪽)가 동시에 고칩니다. 충돌을 막기 위해 트랙별로 나눕니다.

| 브랜치 | 누가 | 무엇 |
|---|---|---|
| `main` | — | 항상 돌아가는 상태. 직접 커밋하지 않습니다 |
| `track-a` | 수경 | A1~A5 지표, B2·B5, D1 |
| `track-c` | 현수 | C1~C5 터전, B4, D2~D4 |
| `track-b` | 윤지 | B1·B3 모델 |
| `docs` | 누구나 | 문서만 고칠 때 (충돌 거의 없음) |

### 규칙 세 개

1. **매일 저녁 자기 브랜치를 main에 머지합니다.** 하루 이상 쌓으면 충돌이 커집니다.
2. **머지 전에 `git pull origin main`으로 받아 와서 자기 브랜치에서 충돌을 해결합니다.** main에서 해결하지 않습니다.
3. **같은 파일을 고칠 때는 함수 단위로 나눕니다.** `features.py`의 카드 업종 분류는 수경, 상가 중분류 분류는 현수입니다. 서로의 함수를 건드리지 않습니다.

```bash
# 하루 시작
git checkout track-a && git pull origin main

# 하루 끝
git add -A && git commit -m "..."
git checkout main && git pull && git merge track-a && git push
git checkout track-a
```

충돌이 났는데 못 풀겠으면 **합치지 말고** 팀에 말합니다. 억지로 합치면 남의 작업이 사라집니다.

## 2. 커밋 메시지

한국어로 쓰고, **무엇을 왜 했는지**를 남깁니다. 2주 뒤에 보고서를 쓸 때 이 메시지가 근거가 됩니다.

```
체류 비중 36칸 산출 (A2)

제과점을 어느 분류에도 넣지 않은 기준으로 계산했습니다.
춘천 남성 50대 7.2% → 80대 2.7%, 12집단 모두 6개월 내내
50대보다 낮습니다.

민감도(제과점을 체류/식사에 넣는 두 경우)는 A5에서 확인합니다.
```

- 첫 줄에 **트랙 코드**를 붙입니다 (`(A2)`, `(C3)`) — 나중에 찾기 쉽습니다
- 수치를 바꾼 커밋에는 **바뀐 값**을 적습니다
- 한계나 미확인 사항이 있으면 그것도 적습니다

### 쓰면 안 되는 숫자

구 분류(통합본) 기준 수치는 **영구히 보고서에 쓰지 않습니다.**

재실행하려면 통합본 코드가 필요한데, 저장소 전체 이력·이전 레포·팀원 로컬 어디에도 없습니다([#14](https://github.com/hsoo23/bigcontest-balgil/issues/14)). **재실행을 기다리는 수치가 아니라 아예 쓰지 않는 수치입니다.** 규정의 최소 요구 성과물이 "재현 가능한 코드 포함"과 참가자의 직접 검증을 요구하므로, 레포에 있는 코드로 다시 만든 값만 씁니다.

- AUC 0.937, 신규 진입 20/38, 급성 AUC 0.874
- 방문 절감 1,069 → 274회, 원인 설명률 19/21일

자세한 목록은 [`실행계획.md`](실행계획.md) 4절·12절에 있습니다.

## 6. 데이터

- **제공 데이터(`data/raw/`)는 git에 올리지 않습니다.** 대회가 준 데이터라 재배포 범위가 불분명하고 용량도 큽니다.
- **외부 공공데이터(`data/external/`)는 git에 올립니다.** 무료·공개 데이터이고 레포가 private이라 배포 문제가 없습니다. 셋이 같은 파일을 쓰지 않으면 조회 조건이 조금만 달라도 수치가 어긋나고, 규정이 **활용한 원본 파일 제출**을 요구하므로 제출 패키지를 만들 때도 한곳에 모여 있어야 합니다.
  - 다만 **GitHub 한도 100MB를 넘는 파일은 `meta.json`(출처·받는 법)만 올립니다.** SGIS 경계 `.shp` 135MB, 상가정보 서울 CSV 302MB가 여기 해당합니다
- **가상 데이터는 파일명과 문서에 "가상"을 반드시 표기합니다.** 제출 체크리스트 10번입니다.

### 외부 데이터를 받으면 세 가지를 남깁니다

규정 원문입니다.

> 외부 공공 데이터 활용 가능(무료·공개 데이터에 한하며, **유료 데이터 사용 시 수상 취소**)
> ※ 단, 외부 데이터 사용 시 **출처 및 수집 방법을 명시**하고, **활용한 원본 파일 제출 필수**

요구가 셋이므로 남길 것도 셋입니다.

| 남길 것 | 어떻게 |
|---|---|
| **원본 파일** | `data/external/<슬러그>/`에 **가공 없이** 둡니다. 열어서 고치지 않습니다 |
| **출처** | 같은 폴더 `meta.json` — 정식 명칭·제공기관·URL·수집일·기준시점·공간단위·라이선스 |
| **수집 방법** | `meta.json`의 `note`에 **조회 조건을 그대로** 적습니다 |

`python scripts/register_external.py`를 돌리면 이 내용이 `docs/external_data.md`에 모이고 **파일 크기와 SHA-256까지 자동 기록**됩니다. 제출본과 분석본이 같은 파일이라는 증거가 됩니다.

> **줄끝 변환을 막아 두었습니다.** `core.autocrlf=true`인 윈도우에서 클론하면 CSV의 LF가 CRLF로 바뀌어 **바이트가 달라지고 기록해 둔 SHA-256과 어긋납니다.** `.gitattributes`에 `data/external/** -text`를 넣어 git이 원본을 건드리지 않게 했습니다. 받은 그대로 보존해야 제출본과 분석본이 같다고 말할 수 있습니다.

### 수집 조건은 문장이 아니라 코드로 남기면 더 좋습니다

화면에서 손으로 받으면 **어떤 조건으로 받았는지가 기록에 남지 않습니다.** 두 달 뒤에 "연령 단위를 5세로 했던가 1세로 했던가"를 기억해야 하고, 다른 사람이 같은 파일을 다시 만들 수 없습니다.

로그인이 없는 공개 통계라면 **받는 스크립트를 같이 올립니다.** `scripts/fetch_mois.py`가 그 예입니다 — 조회 조건이 상수로 적혀 있고, 다시 돌리면 **바이트까지 같은 파일**이 나오는 것을 확인했습니다.

```python
YEAR, MONTH = "2025", "12"      # 분석 기간의 끝. 이 통계표는 검색기간이 1개월로 제한된다
AGE_UNIT = "1"                  # 1세 단위. 10세로 받으면 60~69로 묶여 65세+를 뽑을 수 없다
AGE_FROM, AGE_TO = "0", "100"   # 전체 범위. 65세+만 받으면 분모와 30·40대가 없어진다
```

**왜 그 조건인지를 주석으로 적는 것**이 핵심입니다. 조건만 적으면 나중에 바꿔도 되는지 알 수 없습니다.

로그인·인증키가 필요하거나 화면에서만 받을 수 있으면 스크립트를 못 만듭니다. 그때는 **`meta.json`의 `note`에 클릭 순서와 조회 조건을 문장으로** 남깁니다 — [`데이터_수집_가이드.md`](데이터_수집_가이드.md) B-0이 그 형식입니다.

> 스크립트를 쓸 때 **새 패키지를 끌어오지 않습니다.** `requirements.txt`는 회의에서 함께 올리는 파일이라, `fetch_mois.py`도 표준 라이브러리만 씁니다.

## 7. 인증키

`.env`에만 두고 코드·로그·커밋 어디에도 남기지 않습니다. `.env`는 gitignore입니다.

```
DATA_GO_KR_KEY=...
```

실수로 커밋했으면 **키를 재발급**합니다. 커밋을 지워도 히스토리에 남습니다.
