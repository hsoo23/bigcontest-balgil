# 7. 에이전트 설계 — 주기·도구·판단 (E4)

**담당 수경 · 10/21까지**

> 규정의 최소 요구 성과물 네 번째 — *위험 탐지·판단 로직, 복지자원 추천 체계, 대응 프로세스 및 활용 시나리오*. 그리고 「문제 구성」의 **재현 가능 설명**(판단 기준·위험도 산출 방식·추천 연계 과정을 구체적으로)이 여기서 충족돼야 합니다.

## 7.5 대응 프로세스
〈0~2단계와 종결. 실행은 사람이 한다는 경계〉
> **대응 순서 (#2 확정, 다섯 마디 4번)** — "신호가 오르면 본인에게 먼저 묻고, 닿지 않으면 발길이 닿던 단골이 확인한다." 주황·빨강은 **본인 전화 → (닿지 않으면) 본인이 등록한 발길이 닿던 곳 → 방문 → 기관** 순서입니다(기획안 4절 2단계 "1단계 전화가 비었을 때만"과 같습니다). 단골 안부는 **대면형**에만 붙고, 장보기형은 본인 전화·방문, 병원약국형은 건강 확인·기관 연계입니다(실행계획 3절).
>
> **"단골"은 가게로 못박지 않습니다 (#6)** — 2단계 상대방은 **발길이 닿던 곳(단골 가게 또는 경로당·마을회관)**입니다. 춘천 면 지역은 체류형 점포가 적고 터전점수도 낮아 우선순위에 먼저 오르는데, 경로당은 노인 인구 대비 가장 많습니다(시설 × 터전점수 춘천 −0.80, 현수 #6). 가게가 없는 동에서 단골 가게를 전제하면 신호가 가장 잘 뜨는 곳에서 2단계가 빕니다. D1 `draft_outreach`의 문구 틀도 상대방 종류(가게 / 경로당)를 받아 고르게 짭니다.
>
> **장보기형 업종 (#2 확정)** — 익명 중 장보기 업종(편의점·할인점/슈퍼마켓/양판점·기타식품·농수산물·정육점)만 씁니다. 패스트푸드·주류판매는 익명이지만 넣지 않습니다. `reanalysis/b0_common.py`의 `ESS`와 같고, 넣으면 연휴 잡음이 다시 들어와 끊김 사건이 바뀝니다.
