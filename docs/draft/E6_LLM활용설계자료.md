# LLM 활용 설계자료 

**발길 · 2026 빅콘테스트 AI데이터 활용 분야** 

> ## 규정 근거
>
> 주제설명자료 「데이터 활용 규칙」은 다음과 같이 정합니다.
> *"LLM 등 생성형 AI 활용 가능하며, LLM 활용 여부는 평가에 반영하지 않음 ※ 단, **LLM 활용 시 구체적인 활용 방법 및 분석 과정에 대한 설명자료 제출 필수**"*
>
> 이 문서가 그 설명자료입니다.

---

## 1. 한 줄 요약

**판단은 모델과 규칙이 하고, LLM을 붙인다면 이미 나온 판단을 사람 말로 푸는 자리에만 붙입니다.** 위험도 산출·끊김 판정·개인 지목에는 LLM이 관여하지 않습니다. 이번 제출 범위에서는 그 자리도 고정 문장 틀로 구현해, LLM을 한 번도 호출하지 않습니다(5.3).

## 2. 어디에 쓰고 어디에 안 쓰는가

「이번 구현」 칸은 제출한 코드가 실제로 하는 일이고, 「LLM을 붙인다면」 칸은 설계입니다. LLM을 붙일 칸은 셋이지만, 이번에는 셋 모두 고정 틀이나 규칙으로 구현했습니다.

| | 이번 구현 | LLM을 붙인다면 | 이유 |
|---|---|---|---|
| 발길의 양·질·터전 산출과 우선순위 | 모델·규칙 | 붙이지 않음 | 재현·검증이 가능해야 함 |
| 끊김 판정 | 규칙 (평소 흔들림의 3배, 07절 7.3) | 붙이지 않음 | 임계값이 수치로 남아야 함 |
| 충격 보정 | **규칙** | 붙이지 않음 | 전 연령 대조로 계산 |
| 명부 교차·정렬 | **규칙** | 붙이지 않음 | 개인정보가 규칙 경로에서만 움직임 |
| 상대방 가게 지목 | **규칙** | 붙이지 않음 | 업종 집중도 계산 |
| 근거를 사람 말로 풀기 | **고정 문장 틀** (`draft_outreach`) | LLM — 첫 자리. 수치는 슬롯 그대로(5.2) | 담당자가 3초에 이해해야 함 |
| 자원 후보 우선순위 제안 | **규칙 정렬** (`match_resource`) | LLM — 후보마다 이유 풀기 | 맥락 판단이 필요 |
| 전화 대본·문의 문구 | **고정 문장 틀** (`inquiry_script`) | LLM — 상황에 맞춘 문구 | 상황마다 달라야 함 |
| 전화·문의·방문 실행 | **사람** | 사람 | 에이전트는 제안까지 |

기획안 5절의 도구 11개 중 LLM을 붙일 자리로 설계한 것은 `draft_outreach` 하나였습니다. 나머지 10개(`measure_breadth`, `measure_quality`, `detect_break`, `correct_shock`, `map_ground`, `rate_state`, `match_roster`, `find_counterpart`, `match_resource`, `log_outcome`)는 처음부터 모델과 규칙입니다. 구현 과정에서 도구가 일곱개 늘어 18개가 됐고(07절 7.2), `draft_outreach`와 `inquiry_script`를 포함해 **18개 모두 LLM을 호출하지 않습니다**(5.3).

## 3. 왜 이렇게 나눴는가

이유는 세 가지입니다.

**첫째, 검증 가능해야 합니다.** 규정은 "분석 결과 및 제안 내용에 대한 참가자의 직접적인 검증 및 설명이 가능해야 함"을 요구합니다. 위험도가 생성 모델에서 나오면 왜 그 값인지 재현할 수 없습니다.

**둘째, 오탐의 비용을 낮춥니다.** LLM이 판단까지 하면 틀렸을 때 원인을 추적할 수 없습니다. 판단을 수치로 남기면 틀린 건을 임계값 조정으로 되먹일 수 있습니다(종결 기록 → 임계값).

**셋째, 개인정보 보호입니다.** 4절에서 설명합니다.

## 4. 개인정보 — LLM 입력에 무엇이 들어가는가

**돌봄 명부는 LLM에 들어가지 않습니다.** 명부 교차는 규칙 경로에서만 일어나고, LLM에는 그 결과의 집계 수준 설명만 전달합니다.

| | LLM 입력에 | |
|---|---|---|
| 집단 식별자 (시군구 × 성 × 연령대) | 들어감 | 지표 패널 36칸 중 하나. 개인이 아님 (모델 경로는 90대를 빼 32칸) |
| 발길 네 면의 값과 상태 | 들어감 | 이미 산출된 수치 |
| 끊김 종류·기간 | 들어감 | |
| 추천 자원 후보 목록 | 들어감 | 공개 데이터 |
| **이름·연락처·주소** | **안 들어감** | 명부는 규칙 경로에만 |
| 개인 단위 결제 내역 | **안 들어감** | 제공 데이터 자체가 비식별·집계 |
| 본인 등록 단골 가게의 상호 | **안 들어감** | 지목은 규칙이 하고, 문구만 LLM이 씀 |

제공 데이터는 처음부터 *"개인 및 개별 가맹점 식별이 불가능하도록 집계·비식별 형태"*로 제공됩니다. 따라서 제공 데이터에서 개인정보가 LLM으로 넘어갈 경로는 없고, 남은 위험인 돌봄 명부는 규칙 경로 안에서만 다룹니다.

## 5. 입출력 설계

### 5.1 적용 지점 세 곳

| 지점 | 입력 | 출력 | 형식 |
|---|---|---|---|
| 근거 풀기 | 상태 판정 결과 + 네 면의 값 | 담당자용 2~3문장 | 고정 문장 틀 + 수치 슬롯 |
| 자원 제안 | 상태 + 동 터전 지수 + 자원 후보 | 후보 3개와 각각의 이유 | 목록 |
| 대본 생성 | 끊김 종류 + 상황 | 전화 도입부·문의 문구 | 자유 문장 |

### 5.2 수치는 슬롯으로 주입합니다

생성문이 근거 수치와 어긋나지 않도록, 수치는 LLM이 쓰게 두지 않고 틀에 미리 뚫어 둔 자리에 계산 결과를 넣습니다.

```
"{집단}의 발길이 {기간} 동안 {변화}했습니다. {주된 이유}."
         ↑ 규칙이 채움        ↑ 규칙      ↑ 규칙      ↑ LLM
```

### 5.3 현재 구현 상태 — LLM을 부르지 않습니다

`src/balgil/agent.py` 머리말에

> ` LLM은 부르지 않고, 문장은 고정 틀에 계산값을 슬롯으로 넣는다(5.2)고 적혀 있습니다.`

`draft_outreach`의 독스트링도 고정 문장 틀과 수치 슬롯을 쓰며, 명부의 이름·연락처·주소는 문장에 넣지 않는다(4절)고 적고 있습니다. 함수 본문에서 수치는 모두 f-string 슬롯으로 들어가므로 생성문이 근거와 어긋날 수 없습니다. 5.2의 설계가 코드에 그대로 반영돼 있습니다.

`inquiry_script(kind, agency)`도 같습니다. 슬롯은 기관명 하나뿐이고, 창구 종류(가게 / 경로당·마을회관)에 따라 고정 문구를 고릅니다. 개인정보가 들어갈 자리가 없습니다.

| 적용 지점 | 현재 |
|---|---|
| 근거를 사람 말로 풀기 | 고정 문장 틀 (`draft_outreach`) — LLM 호출 없음 |
| 전화 대본·문의 문구 | 고정 문장 틀 (`inquiry_script`) — LLM 호출 없음 |
| 자원 후보 우선순위 제안 | 규칙 정렬 (`match_resource`) — 거리·반복성·대면성 점수, LLM 호출 없음 |

따라서 이번 제출 범위에서 LLM은 한 번도 호출되지 않습니다. 이 문서는 LLM을 쓴다면 어디에 어떻게 쓸 것인가에 대한 설계이고, 규정이 요구하는 「활용 방법」에 대한 답은 「활용하지 않음」입니다.

규정은 LLM 활용 여부를 평가에 반영하지 않는다고 정하고 있습니다. LLM을 호출하지 않으면 판단이 모두 재현 가능한 수치로 남으므로, 참가자가 직접 검증하고 설명할 수 있어야 한다는 요구에도 맞습니다.

## 6. 실패했을 때

| 상황 | 동작 |
|---|---|
| LLM 호출 실패·지연 | 고정 문장 틀로 그대로 출력. 알림은 멈추지 않습니다 |
| 생성문에 수치가 섞여 나옴 | 슬롯 외 숫자는 후처리에서 제거 |
| 생성문이 근거와 다른 주장을 함 | 담당자 화면에 원 수치를 같이 표시해 사람이 대조 |
| 자원 후보가 비어 있음 | 추천을 생략하고 상태만 전달 |

## 7. 평가에 쓰지 않습니다

규정이 LLM 활용 여부를 평가에 반영하지 않는다고 정했으므로, 발표자료와 보고서에서 LLM을 성과로 내세우지 않습니다. 이 문서는 제출 의무를 충족하기 위한 설명자료입니다. 보고서 본문에서 LLM은 호출하지 않는다는 사실과 개인정보 경계로만 나옵니다. 07절 7.6(모델과 LLM이 하는 일)이 중심이고, 06절 자원 정렬, 08절 머리말과 등록장소, 10절 10.4에서 같은 내용을 짧게 다룹니다.

## 8. 한계

- 고정 틀 문구의 **담당자 수용도를 조사하지 않았습니다.** 3초에 이해되는지는 가정입니다
- 적용 지점 세 곳 중 LLM으로 구현한 것은 없습니다(5.3). 두 곳은 고정 틀, 한 곳(자원 후보)은 규칙 정렬로 구현했습니다
- 같은 입력에 대한 출력 변동성을 측정하지 않았습니다
