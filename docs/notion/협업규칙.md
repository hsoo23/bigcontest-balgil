# 발길 — 협업 규칙

브랜치·커밋·수치 출처·작업 메모 규칙입니다. 10/10 회의에서 확정합니다.

> **문서 세 개가 한 세트입니다.** 「발길 — 기획안」은 무엇을 만드는가, 「발길 — 분석 결과」는 그 근거, 「발길 — 추진 계획」은 누가 언제 무엇을 하는가입니다. 여기에 「발길 — 제출 요건」(마감과 규정), 「발길 — 제출물 목차와 서식」(무엇을 어떻게 쓰는가), 「발길 — 설계자료 2종 요구 항목」(규정상 함께 내는 것)이 붙습니다.

---

셋이 18일 안에 병렬로 일하면서 **서로 깨뜨리지 않기 위한 최소 규칙**입니다. 10/10 회의에서 확정합니다.

---

## 1. 브랜치

같은 `features.py`를 수경(카드 쪽)과 현수(상가 쪽)가 동시에 고칩니다. 충돌을 막기 위해 트랙별로 나눕니다.

| 브랜치 | 누가 | 무엇 |
|---|---|---|
| `main` | — | 항상 돌아가는 상태. 직접 커밋하지 않습니다 |
| `track-a` | 수경 | A1~A5 지표, B2·B5, D1 |
| `track-c` | 현수 | C1~C5 터전, B4, D2~D4 |
| `track-b` | 윤지 | B1·B3 모델 |
| `docs` | 누구나 | 문서만 고칠 때 (충돌 거의 없음) |

### 규칙 세 개

1. **매일 저녁 자기 브랜치를 main에 머지합니다.** 하루 이상 쌓으면 충돌이 커집니다.
2. **머지 전에 `git pull origin main`으로 받아 와서 자기 브랜치에서 충돌을 해결합니다.** main에서 해결하지 않습니다.
3. **같은 파일을 고칠 때는 함수 단위로 나눕니다.** `features.py`의 카드 업종 분류는 수경, 상가 중분류 분류는 현수입니다. 서로의 함수를 건드리지 않습니다.

```bash
# 하루 시작
git checkout track-a && git pull origin main

# 하루 끝
git add -A && git commit -m "..."
git checkout main && git pull && git merge track-a && git push
git checkout track-a
```

충돌이 났는데 못 풀겠으면 **합치지 말고** 팀에 말합니다. 억지로 합치면 남의 작업이 사라집니다.

## 2. 커밋 메시지

한국어로 쓰고, **무엇을 왜 했는지**를 남깁니다. 2주 뒤에 보고서를 쓸 때 이 메시지가 근거가 됩니다.

```
체류 비중 36칸 산출 (A2)

제과점을 어느 분류에도 넣지 않은 기준으로 계산했습니다.
춘천 남성 50대 7.2% → 80대 2.7%, 12집단 모두 6개월 내내
50대보다 낮습니다.

민감도(제과점을 체류/식사에 넣는 두 경우)는 A5에서 확인합니다.
```

- 첫 줄에 **트랙 코드**를 붙입니다 (`(A2)`, `(C3)`) — 나중에 찾기 쉽습니다
- 수치를 바꾼 커밋에는 **바뀐 값**을 적습니다
- 한계나 미확인 사항이 있으면 그것도 적습니다

## 4. 작업 메모

**분석이 끝날 때마다 몇 줄 남깁니다.** 2주 뒤에는 왜 그렇게 했는지 기억나지 않습니다. 직후에 쓰면 10~20분이고, 나중에 쓰면 반나절입니다.

메모는 커밋 메시지에 쓰거나 `docs/memo/` 아래에 날짜로 남깁니다. 형식은 세 줄이면 충분합니다.

```
무엇을 했나 — 체류 비중을 제과점 제외 기준으로 36칸 재계산
숫자 — 춘천 남성 50대 7.2% → 80대 2.7%
한계 — 제과점 포함 시 어떻게 되는지는 A5에서 확인
```

이 메모가 10/20~21 공동 작성일에 문장으로 바뀝니다. 메모가 없으면 그날 분석을 다시 들여다봐야 합니다.

## 5. 쓰면 안 되는 문장

**「발길 — 추진 계획」** 1-2절에 **보고서에 쓰면 안 되는 문장 10개**가 있습니다. 근거를 넘는 주장이거나 데이터로 반박되는 것들입니다.

**각자 자기가 쓰는 절에서 지킵니다.** 윤지가 통합 편집에서 혼자 걸러내기는 어렵습니다.

특히 자주 미끄러지는 것

| 쓰고 싶어지는 말 | 대신 |
|---|---|
| "대면이 먼저 끊기고 필수가 따라 끊긴다" | "끊김은 세 종류로 나타난다" |
| "모델이 새 위험을 예측한다" | "한 주 먼저 잡았다. 새 진입 31건의 소표본이다" |

| "북산면 관계형 점포 0개" | "60세+ 천 명당 20~200배 격차" |

## 6. 데이터

- **제공 데이터(`data/raw/`)는 git에 올리지 않습니다.** 대회가 준 데이터라 재배포 범위가 불분명하고 용량도 큽니다.
- **외부 공공데이터(`data/external/`)는 git에 올립니다.** 무료·공개 데이터이고 레포가 private이라 배포 문제가 없습니다. 셋이 같은 파일을 쓰지 않으면 조회 조건이 조금만 달라도 수치가 어긋나고, 규정이 **활용한 원본 파일 제출**을 요구하므로 제출 패키지를 만들 때도 한곳에 모여 있어야 합니다. (10/10 승인 대상)
  - 다만 **파일 하나가 20MB를 넘으면 올리기 전에 상의합니다.** 상가정보처럼 큰 데이터가 들어오면 레포가 무거워집니다
- 외부 데이터를 새로 받으면 **출처·수집일·라이선스를 `docs/external_data.md`에 기록**합니다 (`scripts/register_external.py`가 해시까지 자동 기록).
- **가상 데이터는 파일명과 문서에 "가상"을 반드시 표기합니다.** 제출 체크리스트 9번입니다.

## 7. 인증키

`.env`에만 두고 코드·로그·커밋 어디에도 남기지 않습니다. `.env`는 gitignore입니다.

```
DATA_GO_KR_KEY=...
```

실수로 커밋했으면 **키를 재발급**합니다. 커밋을 지워도 히스토리에 남습니다.
