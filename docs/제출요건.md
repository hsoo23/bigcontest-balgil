PDF 5쪽 「결과물 제출」의 **\* 최소 요구 성과물** 네 가지입니다. **우리 제출물은 이 넷을 모두 덮어야 합니다.**

「문제 구성」의 **필수 포함 요소**도 네 가지로, 위와 짝이 맞습니다 — 데이터 기반 인사이트 / AI 에이전트 설계 / 운영 흐름 / **재현 가능 설명**(판단 기준·위험도 산출 방식·추천 연계 과정을 구체적으로). LLM 활용은 **"선택 요소 – 권장"**입니다.

> **예시와 다른 점 하나.** 「설명」의 예시는 *"'고립 위험도'를 5단계로 실시간 지수화"*인데 우리는 **네 상태**(좁아짐·끊김·터전 없음·정상)입니다. 예시이지 요구가 아니므로 그대로 갑니다 — 다만 **왜 단계가 아니라 종류인지**를 발표자료 6장에서 한 줄로 설명합니다. 끊김과 터전 없음은 심각도 순서가 아니라 처방이 반대인 별개의 상태이기 때문입니다.

## 5. 계획과 다른 것 네 가지

### ① 마감은 10/25(일)이 아니라 **10/26(월)**

하루가 늘었습니다. 회의 ③(10/24)은 그대로 두고 **10/25(일)을 예비일, 10/26(월) 오전 제출**로 밀었습니다.

### ② 본 제출물은 보고서가 아니라 **발표자료**다

페이지 문구가 *"결과물은 발표자료 형태로 제출"*입니다. **보고서는 "기타자료"에 해당합니다.**

계획은 반대로 짜여 있습니다 — E1 본 보고서를 본체로 두고 E7 발표 자료를 10/23 맨 마지막 작업으로 뒀습니다. 그대로 가면 **제출 이틀 전에 본 제출물을 처음 만들기 시작**합니다.

1차 배점의 완성도 10점에 **"시각적 완성도"**가 명시돼 있고, 2차는 발표 구성이 40점입니다. 발표자료를 늦게 만들면 두 군데서 깎입니다.

> **10/10 회의 안건.** 제안: 발표자료를 10/13 뼈대 → 10/17 수치 동결 직후 1차 완성 → 10/20~21 공동 작성일에 손보는 순서로 올리고, 보고서는 기타자료로 내려 같은 내용의 상세판으로 둡니다.

### ③ LLM은 점수를 주지 않는다

규정 원문: **"LLM 등 생성형 AI 활용 가능하며, LLM 활용 여부는 평가에 반영하지 않음"**. 「문제 구성」에서도 LLM은 **선택 요소**입니다.

**그래서 발표자료에서 LLM을 세일즈 포인트로 쓰지 않습니다.** 쓰면 설명자료 제출 의무만 생기고 점수는 오르지 않습니다. 우리 설계(판단은 모델·규칙, LLM은 사람 말로 푸는 자리에만)는 이 규정과 방향이 같습니다 — 그 분담 자체를 **개인정보 보호 설계**로 설명하고, LLM 자랑으로 설명하지 않습니다.

### ④ 참가신청은 접수돼 있습니다 (확인 완료)

구글폼 접수가 **10/8(목)에 마감**됐습니다. 마감이 지난 뒤에 발견한 것이라 한때 위험 항목이었는데, **10/9에 확인했습니다** — 데이터셋을 받았고 신청 내역도 직접 확인했습니다.

공지 원문이 *"데이터셋은 신청자(팀)에 한해 9/15일부터 매주 화·금에 팀장 메일로 일괄 발송"*이므로, 데이터를 받았다는 것 자체가 접수의 증거이기도 합니다. **더 할 일 없습니다.**

### 보내기 전 확인

1. **첨부가 다 붙었는가** — 1 · 2번 목록은 PDF 넷 + zip 셋, **일곱 개**입니다. 메일의 첨부 수를 센다
2. **〈 〉가 남아 있지 않은가** — 폴더 링크 · 3번 표의 크기와 해시 · 보내는 사람 이름 (팀명은 10/18에 채웠습니다)
3. **가상 데이터에 「가상」이 붙어 있는가** — 파일명과 `비고` 열 양쪽
4. **발표자료·보고서의 숫자가 최종 수치표와 같은가** — `python scripts/check_numbers.py`
5. **보낸 메일과 첨부 목록을 캡처해 둔다** — 접수 증거
6. **첨부 합계가 25MB 아래인가** — `python scripts/build_package.py`의 「큰 것은 링크」 줄이 PDF 넷에 남는 자리를 찍습니다. PDF 넷을 그 안에 넣습니다. 넘으면 화면 캡처가 든 발표 PDF부터 이미지 품질을 낮춰 다시 뜹니다
7. **드라이브 폴더를 로그아웃한 창에서 연다** — 시크릿 창에서 링크를 열어 파일 넷이 보이고 내려받아지는지 확인한다. 폴더 안 파일 이름은 3번 표와 글자까지 같아야 한다
8. **3번 표의 해시는 올린 그 zip에서 잰다** — zip은 묶는 PC마다 바이트가 달라질 수 있어, `external_data.md`의 CSV 해시나 다른 PC에서 잰 값으로 대신하지 않는다. 드라이브에 올린 파일을 그 PC에서 잰다 — Mac `shasum -a 256 <파일>`, 윈도우 `certutil -hashfile <파일> SHA256`

### 드라이브 폴더 만드는 법

- **제출용 폴더를 작업 폴더와 따로** 만듭니다(예: 「또커톤_빅콘테스트_제출」). 마감 뒤 손대지 않기 쉽게 하려는 것입니다. 고칠 것이 생기면 폴더를 건드리지 않고 사무국에 메일로 다시 보냅니다 — 그래야 본문 해시가 계속 맞습니다
- 공유는 **「링크가 있는 모든 사용자 · 뷰어」** 하나만 겁니다. 파일마다 따로 걸지 않습니다
- 넣는 것은 3번 표의 zip 넷입니다. 상가 강원 · 화면캡처 zip은 `python scripts/build_package.py`가 `reports/package/`에 만듭니다. 상가 서울 · SGIS zip은 원본이 있는 PC에서 아래처럼 묶습니다(Mac · 리눅스. 윈도우는 탐색기에서 같은 파일을 골라 「압축」하고 이름을 맞춥니다)

```
mkdir -p reports/package       # 저장소 맨 위에서. build_package.py 를 먼저 돌렸으면 이미 있습니다
cd data/external/sbiz_store   && zip -9 ../../../reports/package/발길_외부데이터원본_상가서울.zip "소상공인시장진흥공단_상가(상권)정보_서울_202606.csv"
cd ../sgis_boundary            && zip -9 ../../../reports/package/발길_외부데이터원본_SGIS경계.zip bnd_dong_00_2025_2Q.*
```
