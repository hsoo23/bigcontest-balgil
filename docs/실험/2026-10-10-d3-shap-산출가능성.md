# D3 「발길 상세」의 SHAP을 재분석 모델로 낼 수 있는가

> 날짜 2026-10-10 · 사람 윤지 · 관련 [#14](https://github.com/hsoo23/bigcontest-balgil/issues/14) · PR #18 · PR #19

## 무엇을 알고 싶었나

재분석 좁아짐 분류 모델에서 화면에 쓸 SHAP 기여도를 낼 수 있는지, 낼 수 있다면 어떤 단위로 무엇까지 설명되는지.

## 왜 그걸 물었나

`#14`가 「D3 「발길 상세」의 SHAP — 통합본 모델 기준 → 재분석 좁아짐 분류 모델로 계산 가능한지 **확인 필요**」로 남겨 두었다. 통합본 모델 코드가 없어졌으므로 재분석 모델로 대체할 수 있는지가 D3 화면 설계를 막고 있었다. "확인 필요"로 두면 현수가 화면을 그릴 때 그 칸을 비워 둘 수밖에 없다.

## 조건

| | |
|---|---|
| 코드 | `reanalysis/b3_models.py`의 모델 ① 정의를 그대로 재현 (`RandomForestClassifier(n_estimators=300, min_samples_leaf=5, class_weight='balanced', random_state=0)`) |
| 데이터 | `reanalysis/reference/weekly_panel.csv` (PR #12로 main에 들어온 커밋된 기준 파일) |
| 환경 | Python 3.10.10 · `scikit-learn 1.7.2`(고정값 일치) · `pandas 2.3.3` · `shap 0.48.0` |

변수 11개: `breadth_z, stay_z, narrow, d_narrow, d_stay_z, d_breadth_z, m3, meal, anon, med, evening`

## 방법

1. `weekly_panel.csv`를 읽어 `y` 결측 행을 버린다 (800행).
2. 위 하이퍼파라미터로 모델을 학습한다.
3. `shap.TreeExplainer`로 `check_additivity=True`를 걸고 SHAP 값을 구한다.
4. 한 칸(춘천 여성 80대 24주)의 상위 5개 기여 합 + 기준값이 모델 확률과 일치하는지 확인한다.
5. 모델 입력 변수 목록에 터전 관련 변수가 있는지 문자열로 검사한다.
6. 패널의 칸 수와 연령대를 세어 지표 패널(`features_segment.csv`)과 비교한다.

## 판단

- **낼 수 있다.** 트리 앙상블이라 `TreeExplainer`가 근사 없이 계산하고, `shap==0.48.0`이 이미 `requirements.txt`에 고정돼 있어 추가 의존성이 없다.
- 조건 두 개를 D3 명세(`실행계획.md` 화면 4개 절)에 적었다. ① **터전 칸은 막대에 넣지 않는다** — 모델이 보지도 않은 변수를 기여도로 보여 주는 셈이다. ② 막대 제목에 「집단 단위 기여도」를 적어 동 단위 터전 칸과 구분한다.
- 단위를 **모델 패널 32칸**으로 적었다. 지표 패널 36칸과 다른 수다.
- 새 진입 31건이므로 SHAP 해석 문장에는 표본 수를 같은 줄에 적는다.
- 현수가 PR #19로 와이어프레임에 그대로 반영했다.

## 예상과 달랐던 것

**터전 변수가 모델 입력에 아예 없었다.** 「발길 상세」는 양·질·연속성·터전 네 면을 한 화면에 보여 주는 설계라, SHAP 막대도 네 면을 설명할 것으로 보고 들어갔다. 그런데 `b4_ground.py`의 동 단위 산출을 모델이 쓰지 않으므로 막대는 네 칸 중 셋만 설명한다. 와이어프레임이 이미 적어 둔 "양·질·연속성은 집단 단위, 터전만 동 단위" 경계와 같은 선이었다.

**모델 패널이 36칸이 아니라 32칸이었다.** `b3_models.py`가 `keep = [a for a in AGES if a != '90대']`로 90대를 뺀다. 그런데 같은 파일 독스트링이 "36칸 × 26주"로 적고 있어 코드와 어긋났다(PR #12에 보고). 더 중요한 건 **36칸이 틀린 수가 아니라는 점**이다 — 지표 패널은 90대를 포함해 36칸이 맞다. 그래서 저장소의 "36칸"을 일괄로 바꾸면 지표 쪽이 전부 틀어진다. 모델을 가리키는 자리만 32다.

**`rank <= 7`이 32칸에서 21.9%다.** "상위 20%"로 적으면 7이 어느 칸 수에서 왔는지 흐려진다(36칸이면 19.4%). 표기를 "상위 7칸(32칸의 21.9%)"으로 통일했다.
