# `agent.py` 입력 형식 — 초안

**D1 · 작성 수경 · 2026-10-12 초안 → 10/17 회의 ②에서 확정 (#6 안건 2)**

현수 D4(가상 데이터)와 D2(본인 등록)가 이 형식에 맞춰 만들고, D1 `agent.py`가 그대로 읽습니다. 확정 전까지 열 이름과 값은 바뀔 수 있습니다. 바꾸고 싶은 곳은 #6에 적어 주세요.

## 0. 단위 원칙 (#14, #20)

- **끊김·좁아짐은 시군구 × 성 × 연령 집단**입니다. 카드 지표는 동에 붙이지 않습니다.
- **명부는 같은 칸(시군구 × 성 × 연령대)으로 거릅니다.** 행정동으로 거르지 않습니다.
- **행정동은 대상자 주소에서만** 가져와 터전(동 단위)과 발길이 닿던 곳 후보를 붙이는 데 씁니다.
- 판정은 실행일 하루가 아니라 **지난 7일 창**입니다.

## 1. 돌봄 명부 (D4) — `match_roster`

CSV, UTF-8. 한 줄이 대상자 한 명입니다. 예시: [`docs/agent_example/roster_example.csv`](agent_example/roster_example.csv)

| 열 | 필수 | 값 | 쓰는 곳 |
|---|---|---|---|
| `대상자ID` | ✅ | 아무 문자열 (예: `P0001`) | 출력에 이 ID만 나갑니다 |
| `시군구` | ✅ | `서울 강남구` / `강원 춘천시` | 칸 거르기 |
| `성` | ✅ | `남성` / `여성` | 칸 거르기 |
| `연령대` | ✅ | `60대` / `70대` / `80대` | 칸 거르기. 끊김 감시 대상과 같습니다 |
| `행정동코드` | ✅ | `data/reference/dong_code.csv`의 `ADM_CD` 8자리 (47개 중 하나) | 터전·발길이 닿던 곳 붙이기 |
| `마지막접촉일` | ✅ | `YYYY-MM-DD` | 오래된 순 정렬 (기획안 4절 0단계) |
| `명부종류` | ✅ | 예: `노인맞춤돌봄`, `독거노인 안전확인`, `기초연금` | 화면 표시 |
| `등록장소ID` | | 2절 `장소ID`. 본인이 등록한 발길이 닿던 곳 (D2) | 2단계 상대방 1순위 |

- **이름·연락처·주소 문자열은 넣지 않아도 됩니다.** 에이전트는 쓰지 않고, 문장 틀과 LLM 입력에도 들어가지 않습니다(E6 4절). 화면 시연에 이름이 필요하면 `이름` 열을 더해도 되지만 출력에는 나가지 않습니다.
- **90대는 넣지 않습니다.** 발길이 부정기해서 끊김 판정을 하지 않습니다(기획안 2절). 넣으면 거르기에서 빠집니다.
- **칸당 인원**: 시연이 "우선순위가 선다"로 보이려면 한 칸(시군구 × 성 × 연령대, 12칸)에 3–4명이 적당합니다(윤지 #20 리뷰). 다만 똑같이 나누면 어느 칸이 걸려도 같아 보이니, 시연할 칸만 조금 두껍게 하는 것을 제안합니다.

## 2. 발길이 닿던 곳 (D4) — `find_counterpart`

기획안 4절 2단계의 상대방 후보입니다. #6 결정으로 **가게만이 아니라 경로당·마을회관도** 들어갑니다(춘천 면 지역은 가게가 적고 경로당이 많습니다).

| 열 | 필수 | 값 |
|---|---|---|
| `장소ID` | ✅ | 아무 문자열 (예: `PL001`) |
| `종류` | ✅ | `가게` / `경로당` / `마을회관` |
| `이름` | ✅ | 가상 상호·시설명 |
| `행정동코드` | ✅ | `ADM_CD` 8자리 |
| `업종` | ✅ | 가게는 **카드 업종 이름**(`data/reference/card_store_map.csv`의 `카드업종`, 예: `한식`·`미용실`·`약국`), 시설은 비움 |
| `게이트키퍼` | ✅ | `Y` / `N` — 지정 가게 여부 |

에이전트는 ① 그 집단의 평소 발길이 닿던 카드 업종 → ② 대상자 동의 같은 업종 장소와 경로당·마을회관 → ③ 게이트키퍼 `Y` 순으로 줄입니다. `등록장소ID`가 있으면 그곳이 맨 위입니다.

**①·②는 D4 없이 이미 됩니다** (`scripts/build_segment_industry.py`).
- **업종 고르기**: 상대방 후보 업종(대면 16개 + 약국) 결제 중 비중 상위 2개에, 같은 도시 전 연령보다 가장 더 몰린 업종(쏠림) 하나를 더해 3개. 비중 3% 미만은 뺍니다. 비중만 보면 어느 집단이나 한식·약국이라, 쏠림이 그 집단다운 곳을 살립니다(예: 춘천 여성 고령 → 한식·약국·**미용실**). 장보기 업종은 "물어도 모른다"(기획안 3절)라 넣지 않습니다.
- **동 점포 수**: 카드 업종을 상가 소분류로 옮기는 대응표 `data/reference/card_store_map.csv`(27줄, #8 D안·#24와 같은 경계)로 행정동마다 셉니다. 상호는 내지 않습니다.
- 카드 업종은 집단 단위 값이고, 동에서는 상가 점포를 셀 뿐이라 카드 지표를 동에 붙이지 않습니다.
- **먼저 물을 창구 (`counterpart_kind`)**: 대상자 동의 상대방 업종 가게 수와 경로당·마을회관 수(`fac_dong`, 현수 C3)를 견줘, **가게가 경로당의 3배가 안 되는 동은 경로당을 먼저** 묻습니다. 지금 기준으로는 춘천 면 지역(북산면 가게 11 : 경로당 11, 사북면 25 : 19 등)만 경로당 창구가 됩니다. 문의 문구도 창구에 맞춰 고릅니다(`inquiry_script`). 3배 기준은 10/17에 같이 정합니다.

- 카드 지표는 `agent_groups`에만 있고 `agent_ground`(동)에는 없습니다.

## 실행

```bash
python scripts/build_segment_industry.py      # 상대방 업종·동 점포 수 (처음 한 번)
python scripts/run_agent.py --as-of 2025-10-01 --roster docs/agent_example/roster_example.csv --out data/processed/agent
```

`--as-of`를 빼면 끊김 자료의 마지막 날(2025-12-31)로 돕니다.
